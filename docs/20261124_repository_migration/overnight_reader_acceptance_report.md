## Fixes made during the shift (candidate, ready for review)

1. **`studies/*/code/export_sessions.py` (8 files)** — `_relative()` used `Path.resolve()`, which follows the study `data/` junction to the main checkout and makes `relative_to(study_checkout)` fail for any reader who links or relocates their data tree (and for the `BCI_DATA_ROOT` layout). Changed to `absolute()`, which preserves the same provenance string for a real checkout. Found via the clean-checkout fresh export of Willett 2021; re-verified by fresh exports for Card, Wairagkar, Kunz, Jude 2026a, and Jude 2026b after the fix.
2. **`studies/20210512_willett/code/step6_decode_batch.py`** — `decode_one()` raised `CalledProcessError` when `latgen_lazy2` exits non-zero ("no endpoint" for sentences the beam cannot complete), aborting the whole bigram decode. Now returns `None` so the sentence counts as `DECODE_FAIL` and the loop continues; re-run completed over all 63 validation sentences (26 decoded).
3. **`docs/20261124_repository_migration/reader_workflow.md`** — documented the two WSL decoder performance facts measured tonight: (a) random graph page reads through `/mnt/<drive>` (drvfs) stall both index build and decode — decode against a Linux-filesystem copy of `TLG.fst` (build ≈ 22 min, decode 880 trials ≈ 23 min warm); (b) the shared graph's page cache (~20 GB) is per-host, so decodes should run serially per machine. The worked example now uses `graph="$HOME/tg5"`.
